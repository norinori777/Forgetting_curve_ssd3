## User Scenarios & Testing *(mandatory)*

### User Story 1 - カード一覧を確認する (Priority: P1)

ログイン済みの学習者は、自分の学習カード一覧を開いて、登録済みカードの概要を確認できる。

**Why this priority**: 一覧の可視化は、検索・絞り込み・一括管理の前提となる基礎価値であり、最小構成でも必要だから。

**Independent Test**: ログイン済みユーザーとしてカード一覧画面を開き、自分のカードが一覧で表示されることを確認できる。

**Acceptance Scenarios**:

1. **Given** ユーザーがログイン済みで自分のカードを保有している, **When** カード一覧画面を開く, **Then** 自分のカード一覧が表示される。
2. **Given** ユーザーがログイン済みで自分のカードを保有していない, **When** カード一覧画面を開く, **Then** 空状態メッセージが表示され、次の操作へ進める。
3. **Given** 他ユーザーのカードが存在する, **When** カード一覧画面を開く, **Then** 他ユーザーのカードは表示されない。

---

### User Story 2 - カードを検索・絞り込む (Priority: P1)

ログイン済みの学習者は、タイトル・問い・答えを部分一致で検索し、カテゴリ・タグ条件で対象カードを絞り込める。

**Why this priority**: 一覧の中から必要なカードを素早く見つける中核機能であり、管理効率に直結するため。

**Independent Test**: 複数の検索条件を適用し、条件に合うカードのみが表示されることを独立して確認できる。

**Acceptance Scenarios**:

1. **Given** カード一覧が表示されている, **When** タイトル・問い・答えのいずれかを入力して検索する, **Then** 一致するカードのみが表示される。
2. **Given** カテゴリまたはタグが選択されている, **When** 検索を実行する, **Then** 選択した条件に一致するカードのみが表示される。
3. **Given** 条件に一致するカードが 0 件である, **When** 検索を実行する, **Then** 空状態メッセージと条件クリア導線が表示される。

---

### User Story 3 - 複数カードを一括管理する (Priority: P2)

ログイン済みの学習者は、検索結果や一覧から複数カードを選び、一括でカテゴリ・タグを付与できる。

**Why this priority**: 複数カードの整理をまとめて行えることで、カード数が増えた場合の負担を下げられるため。

**Independent Test**: 複数カードを選択して一括カテゴリ・タグ付与を実行し、選択したカードにのみ反映されることを確認できる。

**Acceptance Scenarios**:

1. **Given** 検索結果または一覧が表示されている, **When** 複数カードを選択する, **Then** 選択状態が維持される。
2. **Given** 複数カードが選択されている, **When** 一括カテゴリ・タグ付与を実行する, **Then** 選択したカードにのみカテゴリ・タグが反映される。
3. **Given** 一括操作対象が 1 件も選択されていない, **When** 一括操作を実行しようとする, **Then** 実行できず、選択を促す案内が表示される。

---

### User Story 4 - 個別編集・削除とエクスポートを行う (Priority: P2)

ログイン済みの学習者は、カード一覧から個別の編集・削除へ進め、必要に応じて学習データを JSON 単一ファイルでエクスポートできる。

**Why this priority**: 一覧からの遷移とデータ持ち出しは、管理画面としての完結性に必要だが、検索や一覧表示より後順位だから。

**Independent Test**: 一覧から編集・削除導線へ進めること、ならびに JSON エクスポートを開始できることを独立して確認できる。

**Acceptance Scenarios**:

1. **Given** カード一覧が表示されている, **When** あるカードの編集を選ぶ, **Then** 個別編集画面へ遷移できる。
2. **Given** カード一覧が表示されている, **When** あるカードの削除を選ぶ, **Then** 削除確認を経て対象カードを削除できる。
3. **Given** カード一覧が表示されている, **When** エクスポートを選ぶ, **Then** 学習データを JSON 単一ファイルとして出力できる。

### Edge Cases

- 検索条件が複数指定されたときは、すべての条件を組み合わせて絞り込む。
- 一覧の下端到達時は、次の項目を連続表示して閲覧を止めない。
- 選択中のカードが画面更新や再検索で一覧から外れた場合は、選択状態を無効化して誤操作を防ぐ。
- 編集・削除・エクスポートの各導線は、他ユーザーのデータに対しては実行できない。
- 0 件表示時は、空の余白だけで終わらず、条件解除や一覧再表示に戻れる。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは、ログイン済みユーザーに対して自分の学習カード一覧のみを表示しなければならない。
- **FR-002**: システムは、カード一覧画面でタイトル、問い、答えの部分一致検索を提供しなければならない。
- **FR-003**: システムは、カード一覧画面でカテゴリ・タグによる絞り込み検索を提供しなければならない。
- **FR-004**: システムは、検索条件を複数組み合わせて同時に適用できなければならない。
- **FR-005**: システムは、検索結果が 0 件の場合に空状態メッセージと条件クリア導線を表示しなければならない。
- **FR-006**: システムは、カード一覧をページングではなく無限スクロールで表示しなければならない。
- **FR-007**: システムは、検索結果と通常一覧の両方で複数カード選択を許可しなければならない。
- **FR-008**: システムは、選択された複数カードに対してカテゴリ・タグの一括付与を実行できなければならない。
- **FR-009**: システムは、一括操作の対象が未選択の場合に処理を開始してはならない。
- **FR-010**: システムは、カード一覧から個別の編集画面および削除操作へ遷移できる導線を提供しなければならない。
- **FR-011**: システムは、カード一覧から学習データを JSON 単一ファイルとしてエクスポートできなければならない。
- **FR-012**: システムは、カード一覧画面で他ユーザーのカードを表示、選択、更新、削除、またはエクスポート対象に含めてはならない。

### Key Entities *(include if feature involves data)*

- **LearningItem**: 学習カード本体。タイトル、問い、答え、カテゴリ・タグ、作成日時、所有ユーザーを持つ。
- **CategoryTag**: カテゴリまたはタグ。名称、表示属性、所有ユーザーとの関連を持つ。
- **CardListSelection**: 一覧上で選択されたカード集合。検索結果と通常一覧の両方から構成される。
- **ExportPayload**: エクスポート対象の学習データ一式。JSON 単一ファイルとして出力される。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 90% 以上の利用者が、カード一覧画面で自分のカードを 10 秒以内に見つけられる。
- **SC-002**: 90% 以上の利用者が、タイトル・問い・答え・カテゴリ・タグの条件を組み合わせて対象カードを特定できる。
- **SC-003**: 選択した複数カードへの一括カテゴリ・タグ付与が、選択した対象のみで 100% 正しく反映される。
- **SC-004**: 1000 件以上のカードがある状態でも、利用者は閲覧を中断せずに一覧の末尾まで到達できる。
- **SC-005**: 空状態になった利用者の 95% 以上が、条件クリア導線を使って一覧表示に戻れる。

## Assumptions

- 利用者はすでにログイン済みであり、自分のカードのみを操作する前提とする。
- カード一覧画面から実行する編集・削除は、個別カードへの導線までを対象とし、入力画面の詳細仕様は別仕様で扱う。
- エクスポート形式は JSON 単一ファイルとし、インポートは対象外とする。
- 無限スクロールは、一覧の見通しを保ちながら下端到達時に追加読み込みする標準的な挙動を採用する。
- カテゴリ・タグの作成編集そのものは対象外であり、既存のカテゴリ・タグを一覧から関連付ける操作のみを扱う。
- モバイルでも利用可能であることを前提とするが、専用モバイル画面は別要件とする。
